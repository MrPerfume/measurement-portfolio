# 架构与设计决策

## 两类公开可执行证据，不冒充完整系统

v1.1 的新增流程由原生 JavaScript 状态机、Node 测试和真实 Chromium 端到端测试承载。既有 PHP 领域内核保持原样；其 20 项测试不代表覆盖全部新交互。两套代码都不连接私有系统。

```text
demo.json（合成种子、固定参考时刻）
  → createInitialState
  → reduceDemo（唯一状态入口、角色守卫、幂等、失败回滚）
      ├─ domain/weekly.mjs       周单、建议、正式预约、分次到场
      ├─ domain/physical.mjs     接收、送出、提醒、双路径交接
      └─ domain/certificates.mjs 结果、合成证据、关联、人工复核
  → views.mjs（从事实推导数量与闭环）
  → app.mjs（事件委派、渲染、焦点、表单草稿）
```

## 单一事实来源

场景 URL 由 `app.mjs` 作为视图适配处理：只接受六个已知 `scenario` 标识，仍调用既有 `SET_SCENARIO` 转换；History API 只记录地址、不携带角色、对象或表单。前进后退不重新初始化状态，刷新才重新读取合成种子；重置同时移除场景参数。首次直达在页面加载及原生片段定位完成后聚焦演示标题，避免焦点被锚点覆盖。无新数据契约、API 或持久化。

| 状态 | 职责与引用方式 |
| --- | --- |
| `objects` | 设备的权威事实：来源、轮次、到场、结果、证书确认、实物状态 |
| `labRecords[].itemIds` | 送出轮次引用同一批设备，不复制一份在检明细 |
| `weekly.scopeIds` | 发布冻结范围；预约、到场、结果、证书分别计算 |
| `weekly.proposals / appointments / visits` | 建议版本、当前正式预约和已经发生的到场记录互不覆盖 |
| `receipts` | 每次交接的设备集合、去向、时间和合成领取资料 |
| `certificates` | 每份材料独立保存确认结果、关联对象、匹配建议及待确认输入 |
| `ui` | 当前场景对象、队列位置、未提交表单；不作为业务事实 |
| `operations / events` | 操作指纹与审计事实；候选切换不产生新确认事件 |

明细的收件、在检、待领取和已领取状态被所有视图共享。汇总函数从明细推导，不以“整批完成”按钮直接赋值。现场协同不生成收件或送出事实；证书确认不移动实物。

## 状态转换契约

- `reduceDemo(state, action)` 不修改传入状态；业务动作先在副本中校验和执行，失败仅返回错误提示，丢弃全部部分变更。未提交输入仍保留。
- 管理者只读；检测方提出排期建议；计量管理员确认。角色守卫也在状态入口执行，但这只是分工模拟，不是真实身份鉴权。
- 同一操作标识与规范化后的相同载荷安全重放；不同载荷拒绝。设备集合按顺序无关比较，重复 ID 仍是非法输入。失败不占用操作标识。
- 页面成功提交后递增状态版本；业务处理器另有对象级重复检查，防止新操作标识重复生成已存在结果、证书或审计。
- 固定日期为 2026-09-07，固定当前时刻为北京时间 17:00；天数使用 UTC 日期差，实际操作时间按北京时间严格解析，拒绝非法日历日期、未来或倒序时间。
- 刷新或重置都重新构造完整初始状态，包括操作账本、事件、表单、建议版本和队列位置。

这是单页面内存原子性和幂等演示，不是数据库事务、并发锁或跨设备重放的实现。

## 当前任务与反馈定位

- 周单尚未建立时直接显示建单任务；发布后按当前角色展示建议、确认和到场/结果工作。待确认建议始终展开，已处理版本放在可键盘展开的历史区。
- 取回表单只提供仍在检测方的设备，领取表单只提供已回计量室的设备。`ui.forms.returns` 与 `ui.forms.pickup` 分别保存草稿；成功只清当前表单，换轮次两者一起清除。混合状态提供任务定位按钮，不生成业务事件。
- 证书当前工作区在文档阅读顺序中先于队列；顶部原生选择框可切换任何材料。换份后聚焦当前标题并即时定位，操作区同时显示当前证书编号。
- 页面只有一个 live region。重绘前移出、重绘后放入实际提交的表单；多个到场表单用预约 ID 区分。失败聚焦就近反馈并保留输入，不能将“DOM 中有提示”视为用户已经看见。
- 滚动留白与固定页头统一计算，高频操作不引入位移动画；保留键盘焦点与减少动态效果支持。

## 两条独立完成轴

现场对象需要实际执行结果与人工确认的证书；外送对象还需要实物已领取。仅关联证书不算确认；跳过只暂时移出本轮处理，不关闭待办。返回来源按共享对象关联定位原周单或送出轮次；独立关联样例没有伪造来源。

## 构建和运行时

- `index.template.html`：语义 HTML、锚点、分支导航、案例与证据。
- `scripts/build-pages.php`：构建时嵌入合成数据，显式收录模块与三张新案例图，保留原六图画廊。
- `scripts/verify-pages.php`：核对六个具名场景的数据、入口、渲染器、模块导入、CSP、图片与本地引用。
- `.pages-dist/`：可重建的站点产物，不进入 Git。
- 运行时无 API、数据请求、上传、Cookie、浏览器持久化或第三方资源。表单在内存中处理，CSP 使用 `connect-src 'none'` 与 `form-action 'none'`。

锁定的 Playwright 仅为开发依赖；安装下载与浏览器验收使用的本地服务不进入站点产物。

## 保留的 PHP 内核

`src/` 中的校验任务、执行记录、候选评分、送检明细及领域事件，继续演示状态守卫、后补证据、部分回件与幂等。PHP 匹配器输出的是“可关联”判定，不执行真实关联；v1.1 页面仍要求人工确认。真实系统的 Policy/Gate、事务、数据库约束、文件解析与外部通知均在公开范围之外。
